# Channel parameter display units

[Documentation index](../../README.md)

Investigation pointed to separate tables for EQ gain, center frequency, level
coefficients, and pan/balance coefficients. The knob notification reads the
stored mixer parameter after the original setter runs, then reads the original
EQ table entries where physical units are established.

Addresses apply to the [supported main firmware revision](../README.md#supported-revision).

## Display mapping

| Blue selection | Display | Mapping |
| --- | --- | --- |
| HIGH / MID / LOW | `-7.50 dB`, `0.00 dB`, `+3.81 dB` | Original EQ gain table; signed, two decimals |
| FREQ | `815 Hz`, `1.46 kHz` | Original mid EQ frequency table; nearest Hz below 1 kHz, two-decimal kHz above |
| AUX1 / AUX2 / EFX / SUB-MIX / LEVEL | `0%`–`100%` | Nearest integer of `raw × 100 / 127` |
| PAN | `L 25%`, `CENTER`, `R 25%` | Distance from the two-entry center plateau, normalized separately for each side |

Percentages represent **control position**, not amplitude, loudness, or a linear
gain ratio. The underlying level/send DSP curves are nonlinear. No dB labels
are assigned to them in this patch.

The [ZOOM operation manual](https://zoomcorp.com/manuals/l6max-en/) specifies
±15 dB EQ gain and 100 Hz–8 kHz mid frequency. These ranges corroborate the
firmware tables; the per-step values come from the binary rather than an
interpolated curve.

## EQ evidence

The patch reads the original 128-entry float32 EQ gain table at `0x800a5138`
and mid-frequency table at `0x800a5738`. It does not duplicate them in source.

| Raw | Gain | Mid frequency |
| --- | --- | --- |
| 0 | −15.00 dB | 100.0 Hz |
| 32 | −7.50 dB | 285.3 Hz |
| 63 | −0.23 dB | 787.1 Hz |
| 64 | 0.00 dB | 815.1 Hz |
| 65 | +0.24 dB | 845.5 Hz |
| 80 | +3.81 dB | 1456.1 Hz |
| 127 | +15.00 dB | 8000.0 Hz |

The frequency table is nonlinear. Raw 64 is not 1 kHz. The patch reuses the
stored table values directly, without duplicating the tables in source.

## Pan and balance evidence

Raw values 63 and 64 give equal left/right gains; raw 0 is left-only and
raw 127 right-only. Stereo channels use balance rather than mono panning.

The popup uses a position representation:

- Raw 0–62: `L round((63 - raw) × 100 / 63)%`.
- Raw 63–64: `CENTER`.
- Raw 65–127: `R round((raw - 64) × 100 / 63)%`.

This gives `L 100%` and `R 100%` at the ends, and `L 2%` / `R 2%` adjacent
to center. These percentages describe position, not the DSP's gain coefficients
or a measured physical angle. The center plateau is supported by the table;
the choice of L/R percentage notation is a presentation decision.

## Popup layout and validation

The channel number is omitted. The setting title retains the original
seven-pixel font, black ink, and white header band. The single value retains the
original twelve-pixel font, white ink, and centered alignment. It is positioned
at Y=32 in the black body band (Y=18–57), centering its twelve-pixel height.
Both text widgets are centered within the original X=9, width=110 region.

Formatter tests cover signed EQ values, unit changes, percentage endpoints, and
the pan plateau/endpoints. The QEMU smoke test independently formats original
image table entries and compares them with the notification text for all ten
modes. It also checks that the channel text is empty, the value is at Y=32,
expiry restores layout and resources, and encoder reports are neither lost
nor duplicated. Screenshots are generated by firmware LCD transfers.

## Remaining mapping

- LEVEL and send dB conversion and mute thresholds remain unverified.
- PAN notation has not been checked against the official editor's presentation.
- EQ units are table-backed; audio processing itself is unmodeled in QEMU.
- Hardware allocation and update-package validation remain separate work.
